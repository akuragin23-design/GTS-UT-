# Обнуление остатков регистров накопления на дату

Модуль формы внешней обработки: `Form/Форма/Module.bsl`.

Списывает остатки регистров накопления вида «Остатки» на указанную дату документами
`КорректировкаРегистров` с операцией `РучнаяКорректировка`.

## Реквизиты обработки

| Реквизит | Тип | Назначение |
|---|---|---|
| `ДатаОбнуления` | Дата | Момент среза остатков (граница «включая») и дата документов |
| `Организация` | СправочникСсылка.Организации | Необязательный отбор. Для взаиморасчетов — через `АналитикаУчетаПоПартнерам.Организация` |
| `ОбнулятьКлиентов` | Булево | `РасчетыСКлиентами`, `...ПоСрокам`, `...ПоДокументам` |
| `ОбнулятьПоставщиков` | Булево | `РасчетыСПоставщиками`, `...ПоСрокам`, `...ПоДокументам` |
| `ТаблицаРегистров` (ТЧ: `Пометка`, `Имя`) | | Прочие регистры — по одному документу на регистр |

Команда формы: `ВыполнитьОбнуление`.

## Отличия от исходного варианта

- Измерения и ресурсы берутся из метаданных регистра, поэтому обнуляются **все** измерения
  (в т.ч. `Соглашение`, `ДатаВозникновения`, `ЗаказКлиента`/`ЗаказПоставщику`) и **все** ресурсы
  (Упр/Регл, `КОплате`, `КОтгрузке`, `КВозврату`, `ЗалогЗаТару` и т.д.). Неполный набор измерений
  давал остаток `+X` по заполненному ключу и `-X` по пустому — те самые «задвоенные» строки в отчётах.
- Все шесть регистров взаиморасчетов пишутся одним документом, чтобы регл. задание
  `ПроведениеПоРасчетамСПартнерами` не «дораспределяло» рассинхрон между первичным и производными регистрами.
- Документ заполняется через `Заполнить(Неопределено)` + явная `Операция = РучнаяКорректировка`,
  `Ответственный`, `Организация`. Без операции механизмы УТ не считают документ ручной корректировкой.
- Положительные остатки (долг) закрываются `Расходом`, отрицательные (аванс) — `Приходом` по модулю.
  Если в одной строке остатков ресурсы разных знаков, формируются две записи — знак одного ресурса
  не меняет направление всей записи, а в оборотах нет отрицательных сумм.
- Защита от повторного запуска: по дате и маркеру в комментарии
  `Обнуление остатков на dd.MM.yyyy HH:mm:ss:`.
- Всё выполняется в одной транзакции.

## Перед запуском

1. Убедиться, что регл. задание `ПроведениеПоРасчетамСПартнерами` не выполняется в этот момент.
2. Проверить дубли `ОбъектыРасчетов` (запрос №1 в `../ДиагностикаВзаиморасчетов/README.md`) —
   обнуление их не устраняет, а лишь фиксирует.
3. После обнуления проверить остатки на `ДатаОбнуления` запросами из `../ДиагностикаВзаиморасчетов/`.
